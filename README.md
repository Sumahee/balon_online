# BARON ONLINE

가구 제작 업무, 현장 일정, 도면 요청, 자재 구매와 A/S를 관리하는 내부 업무 앱입니다.
Next.js 16.3.4 App Router, React 19, TypeScript, Tailwind CSS 4와 Turso를 사용합니다.

## 택배 송장

왼쪽 메뉴의 **택배 송장**에서 발송일을 지정하고 장부명(또는 거래처/업체명)·적요 열이 있는 .xls/.xlsx 파일을 올립니다. 적요의 선택·착택·선화·착화와 택배/화물 선불·착불 표기를 분류하며, 홈파트너 장부는 홈파트너로 분리합니다. 원본 적요와 자동 제외 목록을 확인하고 받는 분·주소·전화번호·운송구분을 수정할 수 있습니다. 없는 품명과 수량은 빈칸으로 유지합니다.

**송장 저장**을 누르면 `bo_shipping_batches`에 발송일·작성자·전체 송장 스냅샷을 영구 기록합니다. 저장된 송장은 날짜로 조회해 다시 열 수 있고 수정 후 저장하면 이전 기록을 유지한 새 기록으로 남습니다. 직원 세션과 Turso 연결이 필요하며 DB 오류를 임시 저장 성공으로 대체하지 않습니다. 최초 접근 시 전용 테이블과 날짜 인덱스만 생성하며 다른 업무 테이블은 변경하지 않습니다.

바론·홈파트너 엑셀을 각각 다운로드하거나 **인쇄 · 팩스**로 검은 동그라미가 표시된 송장을 인쇄합니다. 13건마다 페이지를 나눕니다. PC 팩스는 시스템 인쇄창에서 HP 팩스 장치를 선택하고 수신번호를 확인해야 합니다. HP PC 팩스 소프트웨어/드라이버 및 전화선 연결이 필요하며 웹앱이 장치를 임의로 선택하거나 팩스 전송 결과를 자동 확인하지 않습니다.

## 실행과 검증

```bash
npm ci
npm run dev
npm test
npx next typegen
npx tsc --noEmit
npm run lint
npm run build
```

Turbopack이 포트 사용 제한으로 실행되지 않는 환경에서는 `npm run build -- --webpack`으로 검증할 수 있습니다.
`.env.local`에는 `.env.example`을 참고해 서버용 Turso 연결 정보를 설정합니다. `JWT_SECRET`도 서버 환경에 필수로 설정합니다. 실제 토큰과 서명 키를 Git에 올리지 않습니다.
기존 DB 초기화 스크립트는 공유 DB에 테이블을 만들기 때문에 테스트 용도로 실행하지 않습니다.

## 업무 흐름

1. 대시보드 또는 업무 관리의 **오늘 확인할 업무**에서 마감 지남, 오늘 마감, 미발주 업무, 긴급 A/S를 확인합니다.
2. 업무명을 눌러 상세 화면에서 현장, 담당자, 도면 사양과 발주 목록을 확인합니다.
3. **대기 → 오피스 → 공장 → 준비완료 → 시공완료** 순서로 업무를 진행합니다. 준비완료는 출고 대기이며 시공완료와 구분합니다.
4. 달력에서 시공·배송·요청 마감을 확인하고 일정을 조정합니다. 업무 검색은 업체명, 현장주소, 지역, 담당자를 포함합니다.
5. 완료 업무는 업무 관리의 **시공완료** 필터에서 확인합니다. 상태 진행 버튼은 완료 업무를 자동으로 다시 접수하지 않습니다.
6. 저장 오류가 표시되면 입력 내용을 유지한 채 다시 저장합니다. **다시 불러오기**는 서버 데이터를 조회하며 실패한 변경을 재전송하지 않습니다.

## 2026-10-06 소스 리뷰와 반영 내용

검토 범위는 전체 소스 구조, 공통 데이터 계층, API 라우팅, DB 스키마, 각 페이지의 주요 조회·저장·상태 전환, 도면 및 사진 흐름입니다.
외부 도면 앱 소스는 이 저장소에 없으므로 검증 범위에서 제외됩니다. 로그인 변경에서는 DB 계정 컬럼과 승인 상태를 읽기 전용으로 확인했습니다.

| 문제 | 반영한 개선 |
| --- | --- |

| DB 변경 쿼리 실패에도 성공 응답 반환 | 업무·A/S·구매·댓글 등록·도면 요청 변경에 실패를 전달하는 변경 쿼리 헬퍼 적용 |
| 구매 데이터가 없거나 조회가 실패하면 예시 구매 내역이 등장 | 빈 DB는 빈 목록 유지, 조회 오류는 실패 응답, 미연결 미리보기의 구매 CRUD는 한 서버 프로세스 안에서 일관되게 유지 |
| 클라이언트와 메모리 저장소가 서로 다른 업무·폴더·이미지 ID 생성 | 업무·A/S ID 유지, 갤러리·자재는 서버 응답의 ID를 사용 |
| 달력·상세·칸반·헤더·간트가 2026년 9월로 고정 | 한국 시간 기준 오늘, 이번 달과 월별 일수 적용. 간트는 월 밖의 업무를 제외하고 월을 걸치는 업무를 잘라 표시 |
| 준비완료를 시공완료로 합산, 완료 업무를 다시 대기로 순환 | 실제 시공완료만 완료율에 반영, 준비완료 집계 분리, 완료 상태 자동 순환 중지 |
| 연락처·포스트바·합판·도면 담당자 변경이 DB에 반영되지 않음 | 업무 사양 4개 필드를 변경 쿼리에 추가. A/S의 업체·주소·사유·연락처·우선순위 등 기존 컬럼 편집도 반영 |
| 화면별로 업무 우선순위 파악이 어려움 | 대시보드와 모바일/데스크톱 업무 페이지에 오늘 확인할 업무와 상세 바로가기 추가 |
| 포커스 표시와 모션 설정이 화면마다 다름 | 공통 키보드 포커스, 비활성 버튼, 움직임 줄이기 설정 적용 |
| 사이드바가 실제 상태와 무관하게 DB 정상 가동이라고 표시 | 조회 중·오류·조회 완료 표시로 변경 |

공통 요청은 15초 제한을 두고 HTTP 상태와 `success` 값을 함께 검사합니다. 조회 실패 시 기존 데이터를 지우지 않습니다.
날짜 계산은 `src/lib/date.ts`, HTTP 응답 검증은 `src/lib/api-client.ts`, DB 변경 오류 처리는 `src/lib/db.ts`에 모았습니다.

## 검증 범위

회귀 테스트는 한국 날짜 경계, 실패 응답, 빈 구매 DB, DB 조회 실패, 미리보기 구매 CRUD, 업무 ID 유지,
DB 등록 실패, 구매 부분 수정, 준비완료/시공완료 집계의 차이를 확인합니다. 실제 운영 DB에 테스트 데이터를 기록하지 않습니다.
프로덕션 빌드와 타입 검사, 모바일 업무 화면 및 데스크톱 대시보드 조회를 확인합니다.
기존 린트 오류가 남아 있으므로 전체 린트 통과와 전체 업무의 종단 테스트 완료를 의미하지 않습니다.

## 직원 로그인

로그인 화면에는 직원 목록을 표시하지 않습니다. 공유 DB의 `users`에 등록된 계정 중
`client_id`가 NULL/0/빈값이고 `status = APPROVED`인 직원만 기존 계정 비밀번호로 로그인합니다.
미등록·승인 대기·외부 업체 계정, 잘못된 비밀번호, DB 조회 실패는 로그인되지 않습니다.
예시 직원 및 임의 계정 발급 경로를 제거했고, 세션 복원 시 직원 자격을 다시 확인합니다.
`/api/users` 직원 목록도 검증된 직원 세션이 있어야 조회할 수 있습니다.
로컬용 서명 키는 `.env.local`에 설정하며 배포 환경에도 별도 `JWT_SECRET` 설정이 필요합니다.
기존 공개 기본키로 발급한 토큰은 인정하지 않으므로 기존 사용자는 다시 로그인해야 합니다.


### 합판 DB 카탈로그

### 도면 프로그램으로 업무 전송

업무 상세의 도면 정보 전송 버튼은 바론 웹을 새 창으로 열어 천정형·옴니버스·에보라 도면의 현장 주소, 업체, 예정일, 연락처, 컬러, 담당자와 요청사항을 채웁니다. 바론 웹에 로그인하지 않았다면 로그인 후 이어서 입력됩니다. 치수는 업무 본문으로 전달되며 자동으로 도면 치수를 추정하지 않습니다.

두 서버가 동일한 Turso DB를 사용해야 합니다. 전송 시 `bo_drawing_handoffs` 테이블이 생성되며, 전체 전송 정보와 15분 유효 전송 키의 SHA-256 해시를 저장합니다. 링크에는 주소·연락처 대신 무작위 키만 포함됩니다. 바론 웹의 `/api/drawing-handoff`와 수신 화면도 함께 배포해야 동작합니다. 로컬 검증 시 `.env.local`의 `BARON_DESIGN_URL`을 바론 웹 개발 서버 주소로 지정합니다. 업무/요청 ID는 도면 프로젝트 정보에 보존됩니다.

### 합판 저장 구조

합판 화면은 `/api/plywoods`에서 공식/수동 등록 데이터와 수정 이미지를 조회합니다. 공식 원본 30종은 `bo_plywood_official`, 수동 등록은 `bo_plywood_samples`, 공식 이미지 수정은 `bo_plywood_image_overrides`에 저장합니다. 이미지 파일 내용도 data URL로 DB에 저장됩니다.

새 DB로 옮길 때 `.env.local`의 Turso 설정 후 `node --env-file=.env.local scripts/import-plywoods.mjs`를 실행하세요. 기존 ID는 덮어쓰지 않으므로 다시 실행해도 수정 내용이 유지됩니다. 원본의 중복 품번 BL-30은 서로 다른 ID로 보존합니다. 실제 인증정보는 Git에 올리지 않습니다.

## 아이폰 웹앱 설치

Safari에서 [BALON 설치 안내](https://balononline.vercel.app/install)를 열고, 공유 → 홈 화면에 추가 → 웹 앱으로 열기(표시되는 경우) → 추가를 선택합니다. 홈 화면의 BALON 아이콘으로 실행하고 기존 직원 계정으로 로그인합니다. Chrome·Edge에서도 브라우저 메뉴의 앱 설치를 사용할 수 있습니다.

웹앱은 업무·도면 조회와 사진 저장 시 인터넷 연결이 필요합니다. 서비스 워커는 공개 오프라인 안내만 저장하며, 업무 API·인증정보·사진·PDF를 캐시하지 않습니다. 새 배포는 네트워크에서 불러오므로 앱을 삭제하고 다시 설치할 필요가 없습니다. /sw.js는 캐시를 사용하지 않도록 응답 헤더를 설정합니다.

## 로그인과 시공자 계정 (1.9beta)

업무 화면과 API는 로그인 후 사용할 수 있습니다. 기존 바론웹과 같은 `users` 계정을 사용하며, `/signup`에서 직원·시공자 가입을 신청할 수 있습니다. 신규 가입은 기존 바론웹 관리자 화면에서 승인해야 합니다. 시공자 계정은 직원 레벨 4와 `manager_rank=시공자`로 저장합니다. 기존 회원을 시공자로 전환할 때도 관리자 화면에서 해당 직함을 설정합니다.

시공자는 달력에 공개된 업무의 상세·첨부·사진·댓글을 조회하고 사진·댓글을 등록할 수 있습니다. 업무 생성·수정·상태 변경·삭제와 사진·댓글 삭제 및 다른 관리 API는 차단됩니다. 메뉴를 숨기는 것과 별도로 API 진입점에서 DB 승인 상태와 현재 등급을 매번 확인합니다.

로그인 세션은 30일 유효하며 기기에 저장된 토큰을 복원하고 인증 성공 시 유효기간을 갱신합니다. 로그아웃하면 해당 기기의 로그인 정보가 제거됩니다. 브라우저·홈 화면 웹앱·Android 앱의 저장 공간은 서로 다를 수 있으므로 처음에는 각 환경에서 로그인해야 합니다.
